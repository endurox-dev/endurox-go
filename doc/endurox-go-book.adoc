== Introduction

This module is set of objects that are bound to Enduro/X C based framework. 
Enduro/X by it self is middleware that uses operating system kernel queues for 
doing high performance inter-process communication. The middleware functionality 
is in the heart of the Enduro/X. Other functionality that comes in the package
is application server, which boots up the processes, monitors them (restarts is
they become dead), detects stalled services.

The processes in Enduro/X are split into to categories:

1. Client processes

2. Server processes

The client processes might be a stand alone process (executables running in system)
or it can be controlled by Enduro/X's Client Process Monitor (cpmsrv). Which gives
administrator nice interface for configuring/starting/stopping the clients.

The server processes are ones that are started by Enduro/X local daemon process
called 'ndrxd'. The server process have inside a thread which conforms the XATMI
server process workflow. At the startup the init function is called. Then threads
goes into waiting on message dispatches (waits on Posix queues). 

Once the application server is going for shutdown or administrator is about to
shutdown single server, then XATMI server process is notified of this action
and server process can gracefully do the de-init and shutdown. The uninit callback
is send to server process while doing shutdown.

== Installation on Linux operating system

To get started with endurox-go module, it is required to install

1. Go compiler and gcc compiler

2. PKG Config package (used by endurox-go) to resolve library dependencies


=== Installing Golang on Linux box

The process of installation should very similar on other operating systems too
(i.e. OSX, FreeBSD, etc.).

Select the Download package from here: https://golang.org/dl/

Enduro/X Go v9 requires Go 1.26 or newer and matching Enduro/X 9
development headers and libraries. The module import path is
`github.com/endurox-dev/endurox-go/v9`.

Particularity sample will run on amd64 on Linux OS:

$ cd ~
$ wget https://golang.org/dl/go1.26.0.linux-amd64.tar.gz
$ sudo tar -C /usr/local -xzf go1.26.0.linux-amd64.tar.gz
$ echo "export PATH=\$PATH:/usr/local/go/bin" > $HOME/.profile
--------------------------------------------------------------------------------

== Trouble shooting

This section lists caveats found during Golang usage.

=== Golang compiler problems

go1.14 introduced use of *SIGURG* for internal purposes of the language runtime.
This causes Enduro/X Unix system calls to interrupt with *EINTR*, which can lead
to incorrect work of the binary using Enduro/X Go bindings.

The bug is reported here: https://github.com/golang/go/issues/50521

While this bug is not fixed, the Enduro/X Go binary shall be started with following
environment variable set:

--------------------------------------------------------------------------------

export GODEBUG="asyncpreemptoff=1"

--------------------------------------------------------------------------------

The setting may be applied to *app.ini* in *[@global]* section as:

--------------------------------------------------------------------------------

[@global]
...
GODEBUG=asyncpreemptoff=1

--------------------------------------------------------------------------------

=== AIX: Invalid GCC invocation from Golang for 64bit mode

If having error such as:

--------------------------------------------------------------------------------

go build && go install
# client
/opt/freeware/lib/golang/pkg/tool/aix_ppc64/link: gcc -Wl,-V failed: exit status 1
/usr/bin/ld: LD 7.2.4(2/13/18)
ld: 0711-738 ERROR: Input file /lib/crt0.o:
        XCOFF32 object files are not allowed in 64-bit mode.
collect2: error: ld returned 8 exit status

--------------------------------------------------------------------------------

Ensure that OBJECT_MODE is not set. As Go compiler at some moment invokes gcc
with out -maix64 flag for some AIX linker tests.

==== Memory leaks when using CGO

If Go code invokes user C code which uses Enduro/X Core API, memory may leak,
if contexting is not done properly. Enduro/X Core libraries require
certain Thread Local Storage (TLS) context, which Enduro/X Go API manages automatically.
By default native OS threads for Enduro/X Go binaries are not associated with
any such context and improper invocation of C code (e.g. via C. namespace), may trigger
Enduro/X Core to allocate new Context and depending on the scenario,
this may happen every time, when accessing such C code from Enduro/X Go code.

The proper way to make such invocations, would be to lock to OS thread (so that threads
does not swap between further calls) and associate it with Enduro/X ATMI context:

--------------------------------------------------------------------------------

func some_work(ac *atmi.ATMICtx) {

        runtime.LockOSThread()
        ac.AssocThreadWithCtx()
        
        C.invoke_c_func_which_does_atmi()

        ac.DisassocThreadFromCtx()
        runtime.UnlockOSThread()

        return
}

--------------------------------------------------------------------------------

The approach is the same as if using Distributed transactions, as described further
in the document, where thread association with context is required.

=== Saga transactions and recovery

A Saga is a pair of actions for work which is committed locally, outside of
the two-phase commit, for example a call to a web service. When the global
transaction commits, *tmsrv* calls the commit action, which confirms the work;
when it is rolled back or times out, *tmsrv* calls the rollback action, which
compensates it. See *tpsagaenlist(3)* for the full description.

A participant fills in a `TpSagaCtl`, registers it with `TpSagaEnlist` inside
the global transaction, does its local work and calls `TpSagaEnd`:

[source,go]
--------------------------------------------------------------------------------
var ctl atmi.TpSagaCtl
if err := ctl.SetSagaName("order"); nil != err {
    return err
}
if err := ctl.SetCommitURL("xatmi://ORDERCOMMIT"); nil != err {
    return err
}
if err := ctl.SetPayload([]byte("order-123")); nil != err {
    return err
}
if err := ctx.TpSagaEnlist(&ctl, 0); nil != err {
    return err
}
branch := ctl.GetBranchXID()
--------------------------------------------------------------------------------

The control types (`TpSagaCtl`, `TpTxStatus`, `TpDlmCtl`, `TpScrCfg`) are
used through getters and setters; a zero value is ready to use. A copy of an
initialized control shares its data with the original, so declare a new
variable for independent data. Setters return an error, and keep the old
value, when the value does not fit. `SetPayload` copies the bytes (at most
`NDRX_SAGA_PAYLOAD_MAX`, 4096) and `GetPayload` returns a copy.

After `TpSagaEnlist`, `GetBranchXID()` returns the branch identifier, which
identifies this participant in all its actions, also after a restart; store
it with the local work. `GetXID()` returns the global transaction identifier.
If the result of the registration is unknown, abort the transaction.

Callback URLs are given explicitly, and the `[@saga]` configuration must
allow them. An empty URL means that the action is not called; at least one of
commit, rollback or after is needed.

`TpSagaEnd` ends the local work; the participant stays registered. When the
Saga configuration has `dlmspace`, it also releases the Saga lock of the
Distributed Lock Manager (DLM) of the Enduro/X Enterprise Edition. In case
if `TPSAGA_NOLOCK` flag is set in `ctl.SetFlags`, `TpSagaEnd` shall not be called.
`TpSagaLeave` removes the participant, so its actions are not called.

Other methods (each takes the control and a separate `flags` argument):

* `TpSagaGet` reads the registered URLs and settings by `SetBranchXID`, also
  during recovery. It does not return the payload.
* `TpSagaUpdate` replaces the payload and URLs while the transaction is active.
  With `TPSAGA_URLSONLY` it replaces only the URLs, also while the transaction
  completes; read the current URLs with `TpSagaGet` first and keep the same
  actions present.
* Set a Saga key to make a repeated registration safe: the same key returns
  the Saga already registered. A key reused with different data fails, unless
  `TPSAGA_UPDATE` is given, which replaces the Saga's data.
* With `TPSAGA_JOINXID`, `TpSagaEnlist` registers in the transaction given by
  `ctl.SetXID`, without the caller being in it.
* `TpTxStatus` and `TpTxRenew` query a transaction and extend its timeout.
  Select the transaction with `SetFlags` and one of `TPTXS_XID` (`SetXID`),
  `TPTXS_BRXID` (`SetBranchXID`) or `TPTXS_TRANID` (`SetTranID` with a
  `TpSuspend` result, or `SetTranIDString`). `TpTxRenew` sets the deadline to
  `SetTimeout` seconds from now. Read the result with `GetStatus`,
  `GetTimeout` and `GetTimeoutLeft`. Their `flags` must be zero.

There are three distinct identifier representations:

* `XID` is an opaque native global identifier. `TpXIDToString` and
  `TpXIDFromString` use the native `TPCONVXID` conversion.
* `GetBranchXID()` returns the participant identifier after `TpSagaEnlist`.
* `TPTRANID` is the native suspend record. `GetTranIDString` and
  `SetTranIDString` use its Base64 representation, compatible with
  `TpSuspendString`. Its format depends on the runtime ABI; do not reuse v8
  tokens with v9.

These bindings provide the native Saga operations. A public native API
for completion by global XID is still needed before implementing the
restincl LRA coordinator close/cancel routes.

=== Resource managers, DLM, and utilities

`TpOpen2(flags)` accepts `TPTXOPENALL`. The `TpRMOpen`, `TpRMClose`,
`TpRMStart`, and `TpRMEnd` methods take a resource-manager name and flags.
`TpGetConnRM(rmid)` returns a borrowed native connection pointer; the
resource manager owns it.

`TpDlmCtl` exposes `Get/SetFlags`, `Get/SetDLMSpace`, `Get/SetSvcName` and
`Get/SetWaitTime`. `TpDLMMkCall(ub, ctl)` prepares a UBF request and updates
the native control; obtain its service name with `ctl.GetSvcName()`. It may replace the buffer. `TpDLMCall(svc, buf, flags)`
also updates the returned buffer and length. `TpDLMACall` and
`TpDLMConnect` return their descriptors. Check both transport errors and
per-command `EX_DLM_RVAL1` results: a successful call can contain a
command failure. The `NDRX_DLM_*`, `EX_DLM_*`, and shared `NE*` constants
are exported, including force deletion and regex unlock flags.

`TpDLMToutGet(waitTime)` returns effective milliseconds, per-attempt
milliseconds, per-attempt ATMI seconds, and an error.
`TpDLMAttemptsGet()` returns the configured limit, not attempts consumed.

`TpBufCmp(left, right, flags)` returns -1, 0, or 1 for a successful
comparison; only -2 means an error. Nil buffers represent native NULL.
`TpExport` retains its Go signature and returns dynamically sized JSON.
`TpExtGetReplyQFD` returns a borrowed pollable descriptor; do not close it.
Unsupported native queue backends return an error.

`TPQCTL.Traceparent` is output-only for enqueue/dequeue. Assigning it does
not select a parent. `TPQKEEPORIG` preserves the native origin metadata.
Queue control marshalling uses the native `CLIENTID` capacity including
its terminating NUL.

=== Tracing and context tags

`TpTraceContextSet/Get` exchange W3C traceparent strings and
`TpTraceStateSet/Get` exchange tracestate strings on an active span. Each takes call flags;
getters return a string and an error. `TpTraceSpanBegin(name, attrs,
flags)` returns a `TpTraceSpan` handle and an error. Pass it to
`TpTraceSpanEnd(span, status, attrs, flags)`. A span is valid only in the
context which started it. Attributes are optional
`*TypedUBF` buffers. `TpTraceEvent(name, attrs, flags)` records an event.

`TpContextTagSet(key, value, flags)`, `TpContextTagClear(key, flags)`, and
`TpContextTagClearAll(flags)` expose the `TPCTXTAG_*` scope and signal
flags. NEXT tags persist until explicitly cleared. Clear request-specific
trace context, state, and tags when reusing a context for another request.

=== Embedded scripting and ownership

An application can run scripts with typed buffers, in a similar way as it
calls services, and scripts can call Go functions. The interpreter comes from
a scripting plugin configured with *NDRX_PLUGINS*, for example the Python
plugin of the separately licensed *endurox-python*. See *tpscrinit(3)* for the
general rules.

`ac.TpScrInit(cfg, flags)` creates a VM (`*TpScrVm`); pass nil as `cfg` for
the plugin defaults. The VM belongs to the context `ac`: scripts run in its
transaction, and the VM is used from one goroutine at a time, like the
context. For parallel work, use one context and one VM per goroutine. No OS
thread locking is needed.

Load scripts with `vm.TpScrLoadStr(name, source, flags)`, or compile them once
with `vm.TpScrComp(source, flags)` and load the result with
`vm.TpScrLoad(name, code.Bytes(), flags)`; release compiled code with
`code.TpScrFree()`. `vm.TpScrUnload` removes a script. The load flags are
`NDRX_TPSCR_PACKAGE`, `NDRX_TPSCR_REPLACE` and `NDRX_TPSCR_FLAT`.

Run a script with `TpScrExec`, using ordinary typed buffers:

[source,go]
--------------------------------------------------------------------------------
func (vm *TpScrVm) TpScrExec(name string,
    param TypedBuffer, input TypedBuffer, flags int64) (TypedBuffer, ATMIError)

type TpScrCallback func(ctx *ATMICtx, vm *TpScrVm, name string,
    param TypedBuffer, input TypedBuffer, user interface{},
    flags int64) (TypedBuffer, ATMIError)
--------------------------------------------------------------------------------

Pass nil for a buffer which is not used. The script may resize the input
buffers; the binding updates them, also when an error is returned. The output
may be the input buffer itself; it is also returned with an error, if the
script gave one. Use `GetBuf()` and the usual typed-buffer casts on the output.

`vm.TpScrRegCB(name, callback, user, flags)` registers a Go function which
scripts can call; `vm.TpScrUnregCB` removes it. The callback receives the
context which owns the VM and the input buffers, valid only during the call.
It changes buffers with their usual methods, returns a typed buffer as output,
or returns an error to fail; `*TpScrError` also carries a script error code. A
callback may run another script of the same `vm`. A callback reached from a
script of a VM of another context fails with `TPEPROTO` without running.

Errors of the scripting methods may be `*TpScrError`, with both `ATMICode` and
`ScriptCode`. `vm.TpScrError()` and `vm.TpScrErrno()` return the script error
message and code; `vm.TpScrSetError(code, message)` sets them, for example in
a callback.

Close the VM with `vm.TpScrUninit(flags)`. `FreeATMICtx()` also closes the
open VMs and compiled code of the context, but does nothing while a VM of the
context runs, for example when it is called from a callback. A context with
open VMs is not garbage collected. Do not use a VM after closing it, even if
closing failed.

=== Binding regression checks

Integration cases are grouped by functional area under `tests/`. Each
case has its own configuration, client, Makefiles and launcher:

* `13_buffer_utils`: comparison ordering, dynamic export/import and
  transport-length selection.
* `14_saga`: real tmsrv registration, status/renewal, suspend/resume,
  participant updates/removal and commit/rollback callback ordering.
* `15_tracing`: context/state round trips, context isolation, spans,
  events, tags and propagation through an XATMI server.
* `16_scripting`: compiler output ownership, callbacks, buffer aliases,
  nested execution, errors and scripting in XATMI service dispatch.
* `17_dlm`: DLM server and Go proxy, SET/GET/DEL, asynchronous replies,
  conversational listing and timeout settings (explicit `-dlm`).
* `18_multi_rm`: two native resources, distinct connection handles, named
  open/close and manual enlistment in client/server transactions.

Build without running the cases:

--------------------------------------------------------------------------------
make -C tests
# Or build one functional area:
make -C tests/15_tracing
--------------------------------------------------------------------------------

From `tests/`, run `./run.sh` for the default suite or a case's `run.sh`
for that area. The default cases use core domains and do not require Enduro/X EE.
Use `./run.sh -dlm` to include the EE DLM case; `-dlm` and `-scripting`
can be supplied independently or together.
Fast scenarios run for 10 seconds by default (NDRX_TEST_DURATATION). Root `go test` does not run them.

Scripting is skipped by default, including direct invocation of its
launcher. It requires separately licensed `endurox-python`. Configure
that scripting plugin and Python environment, then opt in from `tests/`:

--------------------------------------------------------------------------------
./run.sh -scripting
# Or only scripting:
16_scripting/run.sh -scripting
--------------------------------------------------------------------------------

An explicitly enabled scripting case fails if its plugin is unavailable.
See each directory's README for coverage and domain settings. Each area
includes its own XATMI server. DLM tests also require EE `tpdlmsv` on PATH.
Crash recovery and queue trace propagation require additional scenarios.

=== Log Facilities

Enduro/X logging can be configured for different logging sources which includes

User logging can be associated in following levels:

- Per process;

- Per thread (for Go it is Context).

- Per request (associate with Context, i.e. if thread logging enabled, then it can be
promoted to request logging by *ATMICtx.TpLogSetReqFile()*).

*LOG_FACILITY_TP_THREAD* (0x00008) - Settings for TP, thread based logging.

=== Incoming service call information structure - TPSVCINFO
When XATMI server receives request, it receives a control structure with information
about sender and meta data about service which actually is invoked. For example:


--------------------------------------------------------------------------------

package main

import (
        "atmi"
        "fmt"
        "os"
)

//Service func
//Here svc contains the caller infos
func TESTSVC(ac *atmi.ATMICtx, svc *atmi.TPSVCINFO) {

        ac.TpReturn(atmi.TPSUCCESS, 0, &ub, 0)

}

//Server boot/init
func Init(ac *atmi.ATMICtx) int {

        //Advertize TESTSVC
        if err := ac.TpAdvertise("TESTSVC", "TESTSVC", TESTSVC); err != nil {
                fmt.Println(err)
                return atmi.FAIL
        }

        return atmi.SUCCEED
}

//Server shutdown
func Uninit(ac *atmi.ATMICtx) {
        fmt.Println("Server shutting down...")
}


//Server main
func main() {
        //Have some context
        ac, err := atmi.NewATMICtx()

        if nil != err {
                fmt.Errorf("Failed to allocate cotnext!", err)
                os.Exit(atmi.FAIL)
        } else {
                //Run as server
                ac.TpRun(Init, Uninit)
        }
}

--------------------------------------------------------------------------------


TPSVCINFO is defined as follows (with explanatory comments):

--------------------------------------------------------------------------------
//Servic call info
type TPSVCINFO struct {
	Name   string   /* Service name */
	Data   ATMIBuf  /* Buffer type */
	Flags  int64    /* Flags used for service invation */
	Cd     int      /* Call descriptor (generated by client) */
	Cltid  string   /* Client ID string - full client queue name */
	Appkey int64    /* RFU */
	Fname  string   /* Function name invoked (set at TpAdvertise second param) */
	Ctx    *ATMICtx /* ATMI Server Context */
}
--------------------------------------------------------------------------------


The TPSVCINFO.Ctx basically is the same context passed into service function as
first argument.

|func (ac *ATMICtx) FreeATMICtx()
|Description
|Free up the ATMI Context Internally this will call the TpTerm too to termiante
any XATMI client session in progress. Open scripting VMs and compiler outputs
of the context are released first. While a VM of the context is executing (e.g.
when called from its scripting callback) nothing is released: the request is
logged and ignored, and the context stays usable. If compiler output cannot be
released, the context also stays usable, so that TpScrFree can be retried.

and compiler outputs cannot be created on the context..
|Applies
|XATMI client and server

== Typical server process
This section gives an example of typical Enduro/X XATMI server written in Google
Go language. This sample will advertise two services which will make a string buffer
uppercase (the service name will be TOUPPER) and another service which make a string
lower case (service name TOLOWER).

--------------------------------------------------------------------------------
package main

import (
	"atmi"
	"fmt"
	"os"
)

const (
	SUCCEED = 0
	FAIL    = -1
)

func TOUPPER(ac *atmi.ATMICtx, svc *atmi.TPSVCINFO) {

	ret := SUCCEED

	//Get Typed String Handler
	s, _ := ac.CastToString(&svc.Data)

	// Change the buffer
	s.SetString(strings.ToUpper(s.GetString()))
	
	// Send back the response
	ac.TpReturn(atmi.TPSUCCESS, 0, &s, 0)
	
	return
}

func TOLOWER(ac *atmi.ATMICtx, svc *atmi.TPSVCINFO) {

	ret := SUCCEED

	//Get Typed String Handler
	s, _ := ac.CastToString(&svc.Data)

	// Change the buffer
	s.SetString(strings.ToLower(s.GetString()))
	
	// Send back the response
	ac.TpReturn(atmi.TPSUCCESS, 0, &s, 0)
	
	return
}


//Server init
func Init(ac *atmi.ATMICtx) int {

	//Advertize TOUPPER
	if err := ac.TpAdvertise("TOUPPER", "TOUPPER", TOUPPER); err != nil {
		fmt.Println(err)
		return atmi.FAIL
	}
	
	//Advertize TOLOWER
	if err := ac.TpAdvertise("TOLOWER", "TOLOWER", TOLOWER); err != nil {
		fmt.Println(err)
		return atmi.FAIL
	}

	return atmi.SUCCEED
}

//Server shutdown
func Uninit(ac *atmi.ATMICtx) {
	fmt.Println("Server shutting down...")
}

//Executable main entry point
func main() {
	//Have some context
	ac, err := atmi.NewATMICtx()

	if nil != err {
		fmt.Errorf("Failed to allocate cotnext!", err)
		os.Exit(atmi.FAIL)
	} else {
		//Run as server
		ac.TpRun(Init, Uninit)
		
		//Kill the ATMI context
		ac.FreeATMICtx()
	}
}
--------------------------------------------------------------------------------

Note that for simplicity some error handling for service functions are missing.

== Typical client process
This section will give us an example how would client process look for above example,
we will invoke both service to TOUPPER and TOLOWER.

--------------------------------------------------------------------------------
package main

import (
	"atmi"
	"fmt"
	"os"
)

const (
	SUCCEED = 0
	FAIL    = -1
)

//Binary main entry
func main() {

	ret := SUCCEED
	var ac *atmi.ATMICtx
	var err atmi.ATMIError
	//Return to the caller (kind of destructor..)
	defer func() {
		if nil != ac {
			ac.TpTerm()
			ac.FreeATMICtx() // Kill the context
		}
		os.Exit(ret)
	}()

	ac, err = atmi.NewATMICtx()

	if nil != err {
		fmt.Errorf("Failed to allocate cotnext!", err)
		ret = FAIL
		return
	}

	buf, err := ac.NewString("hello world")

	if err != nil {
		ac.TpLogError("ATMI Error %d:[%s]\n", err.Code(), err.Message())
		ret = FAIL
		return
	}

	//Call the server
	if _, err := ac.TpCall("TOUPPER", buf, 0); nil != err {
		ac.TpLogError("ATMI Error %d:[%s]\n", err.Code(), err.Message())
		ret = FAIL
		return
	}

	//Will print "HELLO WORLD"
	fmt.Printf("Got response: [%s]\n", buf.GetString())
	
	//Now call to lower with same buffer
	
	if _, err := ac.TpCall("TOLOWER", buf, 0); nil != err {
		ac.TpLogError("ATMI Error %d:[%s]\n", err.Code(), err.Message())
		ret = FAIL
		return
	}

	//Will print "hello world"
	fmt.Printf("Got response: [%s]\n", buf.GetString())
	
	return
}

== Distributed transaction processing

Distributed transaction currently is supported only for Oracle OCI8 driver which is
bound to Go, the package is available here: https://github.com/endurox-dev/go-oci8

One note must be told, that distributed transaction work according to XA API standard
which sets that transaction is associated with current operating system thread.

Enduro/X acknowledges this fact and provides API call for associating ATMI Context
object with current thread. As Golang Goroutines can be user-space re-scheduled,
thus before associating ATMI Context with OS Thread, you need to *runtime.LockOSThread()* and
then *ac.AssocThreadWithCtx()*.

For example:


--------------------------------------------------------------------------------
func MKCUST(ac *atmi.ATMICtx, svc *atmi.TPSVCINFO) {

        runtime.LockOSThread()
        ac.AssocThreadWithCtx()
        
        // Do the DB works in global transaction
        
        ac.DisassocThreadFromCtx()
        runtime.UnlockOSThread()
        
        ac.TpReturn(atmi.TPSUCCESS, 0, &ub, 0)
        
        return
}
